# Поправки по чату и develop-with-discipline

Проверка от 29 октября 2026, Москва. Исходная ветка: `feature/fuel-level-reed-sensors`, точный исходный commit: `339073c935b75a925f8356f50b26175e204beb0d`. Требования восстановлены из решений пользователя, сверены с действующими исходниками и визуализацией; критерии сохранены в [project-requirements.md](project-requirements.md), рабочий порядок — в [AGENTS.md](../AGENTS.md).

## Что исправлено

| Область | Причина | Поправка и результат проверки |
|---|---|---|
| Веб-навигация | Шесть основных разделов и нижняя панель расходились с четырьмя согласованными страницами | Главная / Управление / Настройки / Сервис; топливо, история, журнал и диагностика вложены; часы, «Домой», свайпы и альтернативы для мыши/клавиатуры |
| Подогрев в вебе | Разрешённый режим менялся сразу после нажатия, не были представлены ожидание/ошибка | Модель запроса с ID, pending/accepted/rejected/timeout; отдельный подтверждённый режим; поздние ответы игнорируются, фактический нагреватель остаётся неизвестным |
| A01: клавиатура | Переключатель раскладки повторно срабатывал при удержании | Смена карты по отпусканию, NO_REPEAT; настоящие pointer-события LVGL и ввод пароля проходят |
| A02: Wi-Fi | Старое соединение могло подтверждать новую команду и приводить к сохранению неверных credentials | Проверяются отключение, результат begin, совпадение SSID и ненулевой IP; отказ сохраняет прежние параметры и фактический статус |
| A03: восстановление | Ошибка записи служебного manifest могла уничтожать пригодную точку отката | Полный prepared-manifest до изменения src, атомарная запись каждой версии, сохранение исходной ошибки и пути backup; регрессия EFBIG после двух записей src проходит |
| A04: BLE | Ненулевой указатель результата ошибочно считался успешным запуском | Проверяемый bool-start и отдельное подтверждение завершения; различаются отказ, пустой результат, отсутствие ответа, отмена; результаты не освобождаются, пока завершение не подтверждено |
| A05: совместимость | Несовместимые overrides MCU/variant или LVGL могли проходить preflight | Проверка известных параметров ESP32-P4 и допустимой версии LVGL; пользовательский INI сохраняется побайтно |
| A06: длинный SSID | Управляющие символы и длина нарушали геометрию выбранной сети | Ограниченная копия для отображения; исходный SSID передаётся без изменения; перекрытий в native-пробах нет |
| A07: нет истории / устаревшая история | Историческая находка аудита | Уже исправлено в исходной топливной ветке; добавлена регрессия, это не заявляется новым исправлением |
| A08: лицензии | Тексты лицензий не попадали в архивы CI | Копирование `licenses/` в артефакты, рекурсивные SHA-256 с относительными путями; два теста упаковки проходят |

Проверенный предыдущий комплект из семи файлов сохранён как `tests/fixtures/v04_fuel/` и распознаётся установщиком точно по хешам. Прежний `v04_before_fuel` также заморожен, чтобы изменение радио не подменяло исторический вход теста. Среди семи управляемых production-исходников изменены только `main.cpp` и `panel_radio.cpp`; логика модели порогов и конфигурация дисплея не переписаны.

## Границы и следующий контроль

Локальные проверки завершены до фиксации коммита. Target-сборка должна выполняться штатным GitHub Actions для опубликованного SHA: `bash ci/bootstrap.sh host`, затем `bash ci/bootstrap.sh firmware`. Итог сборки и ссылки на её артефакты следует смотреть в [PR #2](https://github.com/DeadSoulf/boiler_room/pull/2) и запуске workflow этого SHA. Этот документ сам по себе не заявляет успех ещё не выполненного CI.

Нет аппаратного испытания дисплея/тача, C6/RF, датчиков или нагревателя; устройство не прошивалось. Host-замены SDK не моделируют все особенности FreeRTOS, DHCP и радио. LeakSanitizer в локальной среде отключён. Установщик обеспечивает атомарность отдельной записи manifest, а не всей многофайловой транзакции при потере питания.

Сохранены неопределённости аппаратного проекта: назначение 80 °C, GPIO/NO-NC/дребезг, исполнительное устройство, температурный датчик, регулятор, обратная связь и протокол. Веб-кнопки остаются явно обозначенной демонстрацией. Исторический аудит не переписывался под новый результат.
