# Как повторить дополнительные проверки

Проверяемая версия исходников: `b700ef6f837f5fc1dbd0bad91a569159123c3851`. Проверки хранятся в `docs/audits/2026-10-28/`, а применяются к исходникам, указанным через `--repo`. Если аргумент не задан, runner использует корень checkout, в котором находится этот каталог.

Эти probes подтверждают **наличие известных дефектов**, поэтому их успешный итог нельзя читать как «прошивка исправна». После исправления соответствующий диагностический probe должен перестать подтверждать прежнее ошибочное состояние; затем его следует преобразовать в регрессионный тест правильного поведения. Подробные условия и статусы описаны в README каждой группы.

## Требования

Linux, Python 3.10+, GCC/G++ с AddressSanitizer и UndefinedBehaviorSanitizer, `ar`. Для UI дополнительно нужны исходники LVGL **8.3.11** из проверенного native-артефакта либо точного официального commit `74d0a816a440eea53e030c4f1af842a94f7ce3d3`. Компиляция UI использует реальные исходники LVGL и штатные замены платы/радио из `tests/host`.

Временные результаты лучше размещать вне исходников проекта. Приведённые ниже каталоги являются примерами и должны быть пустыми либо предназначенными только для этих проверок.

## Wi-Fi и BLE

Из корня checkout:

```bash
python3 docs/audits/2026-10-28/probes/radio/run.py \
  --repo . --output /tmp/boiler-audit-radio
```

Результат должен подтвердить ложный успех перехода Wi-Fi, неточную диагностику немедленного отказа begin и ложное завершение BLE. [Описание радиопроверок](probes/radio/README.md) раскрывает заменённые API и происхождение BLE wrapper. Это моделирование SDK, а не радиоиспытание на плате.

## Установщик и восстановление

```bash
python3 docs/audits/2026-10-28/probes/updater/run.py \
  --repo . --output /tmp/boiler-audit-updater
```

Проверки работают на временных копиях fixtures. Проверка постоянного отказа записи устанавливает `RLIMIT_FSIZE` только в своём процессе и снимает его до проверки восстановления. Не следует переносить этот fault injection на рабочий BSP вручную. [Описание проверок установщика](probes/updater/README.md).

## UI с настоящим LVGL

В [GitHub Actions run 40585643270](https://github.com/DeadSoulf/boiler_room/actions/runs/40585643270) native-артефакт содержит `lvgl-native-source.tar.gz`. После распаковки укажите каталог с `lvgl.h` и `src/`. Артефакты исходного workflow хранятся 14 дней; после истечения срока нужны официальные исходники закреплённого commit.

```bash
python3 docs/audits/2026-10-28/probes/ui/run_ui_audit.py \
  --repo . --lvgl /path/to/lvgl-8.3.11 --output /tmp/boiler-audit-ui
```

Штатный baseline должен завершиться успешно. Расширенный probe должен показать три поведенческих отказа клавиатуры с одной общей причиной; runner отличает их от ошибки компиляции или отчёта санитайзера. Снимки многострочного SSID и устаревшей сводки нужны для проверки A06/A07. [Описание UI-проверок](probes/ui/README.md).

LeakSanitizer в исходном аудите был отключён из-за ограничения среды; ASan/UBSan оставались включены. Поэтому отсутствие утечек эти результаты не доказывают.

## Как сверить исходники и доказательства

[evidence/source-manifest.json](evidence/source-manifest.json) содержит 75 путей, размеры, Git blob SHA-1 и SHA-256 исходного снимка. [evidence/verification.json](evidence/verification.json) содержит точный CI run, digest архивов и результат сверки внутренних манифестов. Локальные штатные результаты записаны в [evidence/local-baseline.json](evidence/local-baseline.json).

Материалы этого аудита добавлены отдельным коммитом; исходный `b700ef6…` не содержит самого каталога probes. Поэтому можно использовать checkout ветки аудита с неизменёнными production-файлами или запускать runner из ветки аудита с `--repo`, указывающим отдельный checkout исходного commit. Проверка доступности нового каталога не должна подменять проверку версии исходников.
