# Переносимые проверки радиодефектов

Эти три небольшие программы воспроизводят неправильную обработку отказов в `panel_radio.cpp` на исходниках `DeadSoulf/boiler_room`, commit `b700ef6f837f5fc1dbd0bad91a569159123c3851`. **Exit 0 означает «ожидаемый дефект воспроизведён».** Это диагностические воспроизведения, а не набор тестов для приёмки исправной прошивки. После устранения дефекта соответствующее утверждение намеренно перестанет выполняться.

## Запуск

Зависимости: Python 3.8+ со стандартной библиотекой; Linux/POSIX; `g++` с C++17, AddressSanitizer и UndefinedBehaviorSanitizer. Для `g++` требуются доступные библиотеки выполнения `libasan` и `libubsan`. Arduino, PlatformIO, LVGL, доступ в сеть и физическая панель не нужны. `CXX` или `--cxx` могут задать один исполняемый файл совместимого компилятора. Составные shell-команды в этом параметре не поддерживаются.

После размещения каталога в репозитории путь к корню вычисляется относительно `docs/audits/2026-10-28/probes/radio/run.py`; текущая рабочая папка не влияет на выбор исходников:

```sh
python3 docs/audits/2026-10-28/probes/radio/run.py --help
python3 docs/audits/2026-10-28/probes/radio/run.py
```

Можно проверить другой checkout и указать временную папку для сборки:

```sh
python3 docs/audits/2026-10-28/probes/radio/run.py --repo /path/to/boiler_room --output /tmp/boiler-radio-probes
```

Без `--output` создаётся отдельная временная папка. Она сохраняется после запуска, чтобы можно было изучить три бинарника и `results.json`. В Git следует включать только исходный пакет и нужный JSON с результатами; бинарники в публикацию не входят.

Каждая программа включает `#include "panel_radio.cpp"`; путь к production-коду передаётся как `-I<repo>/src`. Прошивка не копируется в пакет и не изменяется. Заголовки SDK заменяются небольшими локальными stubs. Флаги компилятора: C++17, `-Wall -Wextra -Werror`, ASan/UBSan, `-fno-sanitize-recover=all`, `-fno-omit-frame-pointer`, `-UNDEBUG`. При выполнении установлены `ASAN_OPTIONS=detect_leaks=0:halt_on_error=1` и `UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1`. Проверка утечек отключена; выводов об отсутствии утечек нет.

## Что именно проверяется

| Программа | Условие отказа | Ожидаемое ошибочное поведение проверенного commit |
| --- | --- | --- |
| `repro_wifi_transition.cpp` | Старое соединение остаётся активным; `disconnect()` и новый `begin()` возвращают отказ | Сообщение об отключении противоречит текущему состоянию; запрос новой сети выдан за успех, её credentials записаны, хотя SSID прежний |
| `repro_wifi_begin_failure.cpp` | Старого соединения нет; `begin()` немедленно возвращает отказ | Ошибка старта превращается в сообщение о таймауте через 20 000 мс модельного времени; credentials при этом не записываются |
| `repro_ble.cpp` | Неблокирующий запуск BLE возвращает `false`; точная блокирующая обёртка SDK возвращает ненулевой указатель | UI-сообщение утверждает, что поиск завершён, хотя сканирование не началось |

SSID, IP и пароль в stubs — вымышленные тестовые значения. Задержки увеличивают `fakeMillis`, без реального ожидания 20 секунд. Вызов `xTaskCreate` не создаёт поток, мьютексы упрощены; эти воспроизведения не проверяют планирование FreeRTOS или гонки.

Отказы SDK допускаются его API и подаются через контролируемые stubs. Это подтверждает неправильную реакцию приложения на такие отказы; частоту их возникновения на панели, работу C6/SDIO/RPC, реальные Wi-Fi/BLE-соединения и установленную прошивку эти программы не измеряют. Для BLE включены `CONFIG_ESP_HOSTED_ENABLE_BT_NIMBLE`, `CONFIG_NIMBLE_ENABLED` и `CONFIG_BT_NIMBLE_ROLE_OBSERVER`.

## Коды выхода и результаты

| Код `run.py` | Значение |
| --- | --- |
| `0` | Все три программы собраны, завершились без ошибки, и ожидаемые дефекты наблюдались |
| `1` | Хотя бы одно ожидаемое поведение не подтверждено: например, код уже исправлен, утверждение не прошло или sanitizer завершил процесс |
| `2` | Ошибка аргументов, зависимости, сборки или запуска; таймаут; либо файлы production изменились во время проверки |

`results.json` сохраняет раздельные `compile` и `run` для каждого сценария: команды, `status`, `returncode`, stdout/stderr и продолжительность. Если сборка не удалась, запуск имеет `status: not_run`. Предыдущие попытки сборки в новый отчёт не импортируются. Там же находятся версия Python/компилятора, настройки sanitizer, контрольные суммы исходников и пакета, и проверка неизменности production-файлов. Пути к checkout, пакету и сборке в JSON заменены на `<repo>`, `<probe>` и `<output>`; исполняемые команды используют реальные аргументы без shell.

`baseline.json` фиксирует репозиторий, commit и SHA-256 трёх production-файлов. На другом commit проверки тоже запускаются, но несовпадение хешей явно отражается в отчёте и консоли. Код возврата после изменения прошивки следует разбирать по каждому сценарию, а не считать автоматическим подтверждением исправления всех проблем.

## Происхождение stubs и точной BLE-обёртки

Основные stubs взяты из `tests/radio_stubs` проверенного commit. `WiFi.h` дополнен управляемыми отказами `disconnect()`/`begin()` с сохранением старого состояния; `Preferences.h` фиксирует SSID сохранённого тестового блока. Смещение поля SSID дополнительно проверяется `static_assert` в сценарии перехода Wi-Fi. BLE-заголовки содержат минимальные классы для вызова штатной обёртки и имитацию отказа нижележащего запуска.

Файл `stubs/ble_scan_blocking_wrapper.inc` — **неизменённые строки 790–809** [`libraries/BLE/src/BLEScan.cpp` Arduino-ESP32 3.3.6](https://github.com/espressif/arduino-esp32/blob/3.3.6/libraries/BLE/src/BLEScan.cpp#L790-L809). Это только 20 строк функции `BLEScan::start(uint32_t, bool)`, без больших сторонних исходников. Исходный файл отмечает авторство kolban и добавление NimBLE lucasssvaz на основе работ kolban/h2zero. Git blob SHA-1 полного исходного файла: `54e60a2e4235f98d1d7aacf55d6dabb9b57444a5`; SHA-256 точной выдержки: `9ce88464f34ad596e4d08c4b2f81bba42548ec85afa6925530b503e8343c13f4`. Ссылки, git blob SHA и границы выдержки записаны в `official_sources.json`. Применимая лицензия BLE-библиотеки — **Apache License 2.0**, из [libraries/BLE/LICENSE того же tag](https://github.com/espressif/arduino-esp32/blob/3.3.6/libraries/BLE/LICENSE). В пакет включены её полный текст [UPSTREAM_BLE_LICENSE.txt](UPSTREAM_BLE_LICENSE.txt) и [UPSTREAM_BLE_NOTICE.md](UPSTREAM_BLE_NOTICE.md) с исходным заголовком авторства. Полные файлы SDK не включены.

API Wi-Fi сверено с этой же версией: [`WiFiSTA.cpp`, возврат ошибки `begin()`](https://github.com/espressif/arduino-esp32/blob/3.3.6/libraries/WiFi/src/WiFiSTA.cpp#L83-L92), [`STA.cpp`, неудачный переход со старого соединения](https://github.com/espressif/arduino-esp32/blob/3.3.6/libraries/WiFi/src/STA.cpp#L363-L423), [`STA.cpp`, ошибки и таймаут отключения](https://github.com/espressif/arduino-esp32/blob/3.3.6/libraries/WiFi/src/STA.cpp#L527-L558).
