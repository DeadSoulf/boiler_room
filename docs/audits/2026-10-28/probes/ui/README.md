# Воспроизведение UI-аудита

Проверка предназначена для `DeadSoulf/boiler_room`, исходный проверенный коммит
`b700ef6f837f5fc1dbd0bad91a569159123c3851`. Она собирает штатный host baseline
и дополнительные UI-сценарии с настоящим **LVGL 8.3.11**, ASan и UBSan.
Плата, касания и радио используют имеющиеся host-замены проекта. Прошивка
устройства, сетевые операции и изменение производственных исходников не выполняются.

## Требования

- Python 3.10 или новее; используются только модули стандартной библиотеки.
- `gcc`, `g++`, `ar`; проверено на Linux с GCC.
- Исходники LVGL **8.3.11**. Распакуйте `lvgl-native-source.tar.gz` из native
  артефакта соответствующего GitHub Actions запуска и укажите каталог,
  содержащий `lvgl.h` и `src/`.

LVGL и готовые бинарные файлы в этой папке не распространяются. Runner не
скачивает зависимости. LeakSanitizer отключён (`detect_leaks=0`), поскольку
он несовместим с некоторыми средами под ptrace; проверка утечек не заявляется.

## Запуск

Из корня checkout:

```bash
python3 docs/audits/2026-10-28/probes/ui/run_ui_audit.py \
  --lvgl /tmp/lvgl-8.3.11 \
  --output /tmp/boiler-ui-audit
```

По умолчанию `--repo` определяется относительно положения runner в checkout,
а не относительно текущего рабочего каталога. Для отдельного снимка исходников:

```bash
python3 docs/audits/2026-10-28/probes/ui/run_ui_audit.py \
  --repo /path/to/boiler_room \
  --lvgl /path/to/lvgl-8.3.11 \
  --output /tmp/boiler-ui-audit
```

`--output` должен находиться вне `--repo` и `--lvgl`. Там создаются объекты,
исполняемые файлы, журналы, PPM-кадры и `summary.json`. Отдельный запуск только
штатной проверки:

```bash
python3 docs/audits/2026-10-28/probes/ui/run_ui_audit.py \
  --lvgl /tmp/lvgl-8.3.11 \
  --output /tmp/boiler-ui-baseline \
  --baseline-only
```

Дополнительно доступны `--jobs`, `--timeout`, `--cc`, `--cxx`, `--ar`.
Каждая команда запускается без оболочки; пути с пробелами передаются отдельными
аргументами.

## Как читать результат

| Код runner | Значение |
|---|---|
| `0` | Baseline прошёл; probe не воспроизвёл известный дефект. С `--baseline-only` означает только успешный baseline. |
| `1` | Baseline прошёл, а probe нормально завершился и воспроизвёл известный дефект клавиатуры: `DEFECT REPRODUCED`. |
| `2` | Ошибка окружения, версии LVGL, сборки, baseline, санитайзера или неожиданный отказ probe. Это не подтверждение дефекта клавиатуры. |

На исходном проверенном коммите ожидается:

```text
BASELINE PASS: exit 0; no ASan/UBSan diagnostics
DEFECT REPRODUCED: 3 known keyboard checks failed; probe exit 1
Baseline passed. This is a product-behavior result, not a compile/sanitizer error.
```

`summary.json` сохраняет статусы baseline/probe, найденные отказы клавиатуры
и SHA-256 проверяемых входных файлов. Подробности находятся в `build.log`,
`baseline/baseline.log` и `probes/probes.log`.

## Проверяемые сценарии

`ui_probe.cpp` включает исходный `tests/host/host.cpp` через include path,
переименовывая его `main`; производственные исходники используются напрямую
из выбранного `--repo`.

Три проверки клавиатуры используют pointer-события, включая обычное нажатие
длительностью 60 мс:

1. `q → ABC → Q → 123 → 1` должно дать `qQ1`. На проверенном коммите получается
   `qQ~1`.
2. «abc» из символьной раскладки должна вернуть нижний регистр. На проверенном
   коммите получается верхний.
3. Переход «123» из нижнего регистра не должен менять текст. На проверенном
   коммите в пустое поле добавляется `~`.

Все три отказа относятся к одной ошибке смены раскладки при ещё удерживаемом
пальце. Возврат `1` самим probe означает эти ожидаемые поведенческие отказы;
runner дополнительно проверяет их точный состав и нормальное завершение.

Другие сценарии проверяют длинные SSID, сообщения Wi-Fi/BLE, сохранение поля
при изменениях состояния радио, устаревшие измерения и ручные даты с переходом
летнего времени. Измерения и сетевые состояния в этих сценариях — явно заданные
тестовые данные, а не результаты аппаратных испытаний.

Сообщения `OVERLAP` относятся к прямоугольным рамкам меток. Они сами по себе
не доказывают наложения видимых символов: обычные рамки на главной пересекаются,
но по рендеру символы не накладываются. Сценарий многострочного SSID проверен
визуально и действительно перекрывает подпись «Пароль».

Сведения «Сервиса» при позднем обновлении радио относятся к ограничению
диагностики, поскольку предусмотрена ручная кнопка обновления. Они не включены
в три автоматических отказа клавиатуры.
