## Что означает проверка образа

В [OTA-коде точного source commit](https://github.com/DeadSoulf/boiler_room/blob/15861540101efee44ad36f756f45585e8bff3595/src/panel_update.cpp) установка сравнивает длину и SHA скачанного BIN с манифестом. После записи `esp_ota_end`, `esp_image_verify` и `esp_partition_get_sha256` проверяют образ из Flash; точная длина должна совпасть с манифестом. При следующей загрузке повторно проверяются running image, его сохранённый хеш и ожидаемая версия. После периода здоровой работы интерфейса новый app получает состояние VALID; оно перечитывается, запись Confirmed сохраняется и проверяется. Доступность возврата требует также проверенной предыдущей версии.

По [контракту ESP-IDF 5.5.2 для ESP32-P4](https://docs.espressif.com/projects/esp-idf/en/v5.5.2/esp32p4/api-reference/storage/partition.html#_CPPv424esp_partition_get_sha256PK15esp_partition_tP7uint8_t) хеш, добавленный к app image, проверяется до возврата; повреждённый образ даёт ошибку. Внутренний image digest отличается от SHA всего release BIN.

Итоговый proof явно указывает `readback_method=device OTA image validation`, `device_internal_flash_validation_verified=true`, `independent_external_flash_readback=false`. Существующее поле `readback_and_metadata_verified=true` обозначает **эту внутреннюю проверку и подтверждённые метаданные запуска**, в сочетании с тремя реальными HTTP-наблюдениями. Оно не означает независимое внешнее чтение всех байт приложения или полного свободного хвоста app-раздела. Предварительный локальный сборщик наблюдений оставлял общий readback-флаг false; итоговая квалификация добавлена после независимого разбора фактического кода и наблюдений, без изменения исходных снимков.

## Проверка исправления интерфейса

Ошибка старой версии воспроизведена на живой панели: раскрытый блок закрывался на очередном опросе через 2,832 с. Для финального source v0.10.1 настоящий Chrome прошёл сценарии раскрытия/закрытия, нескольких карточек, сохранения фокуса, клавиатуры и обновления статусов на ширинах 320, 390, 768 и 1280. Обычный интервал опроса — 3 с; 16 циклов, ошибок страницы и мутирующих HTTP-запросов нет. Эти проверки проведены на изолированном стенде встроенной страницы. После OTA проверено точное совпадение живой страницы с этим исходником; отдельная визуальная сессия пользователя после установки не заявляется.

[GitHub OTA + ESP32-P4 CI](https://github.com/DeadSoulf/boiler_room/actions/runs/41983268098) успешен для исходника сборки; профильные проверки также успешны. Старый общий workflow связан с отдельной [issue #15](https://github.com/DeadSoulf/boiler_room/issues/15), весь CI не объявляется зелёным.

## Границы приёмки и дальнейшая работа

Независимый внешний Flash readback после OTA, физическое отключение питания во время записи, фактический возврат, визуальный осмотр/касания, успешный ввод PIN человеком, реальные датчики и MQTT-брокер не проверялись. Готовность тача по статусу не заменяет испытание всех касаний. Доступность rollback не является испытанием отключения питания.

Дальнейшие версии устанавливаются через GitHub OTA по последнему указанию пользователя. Следующая отдельная задача — одинаковый крупный размер четырёх температур на главном экране физической панели и в вебе. Для неё готовится v0.10.2; этот отчёт не утверждает её публикацию или установку. USB используется только по отдельному явному поручению для первоначальной установки или восстановления.
