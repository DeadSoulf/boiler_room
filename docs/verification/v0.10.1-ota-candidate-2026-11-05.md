## Запрос и исправление

Пользователь сообщил, что в веб-разделе «Оборудование» раскрытые блоки сами сворачиваются, и попросил попробовать обновление через GitHub. Затем уточнил порядок: сначала завершить этот этап, после него сделать четыре температуры главного экрана одного размера. Дальнейшие обновления выполняются через GitHub OTA.

Причина подтверждена в настоящем браузере, открывшем живую v0.10.0: после раскрытия электрокотла первый очередной опрос закрыл блок через **2,832 секунды**. Проверка выполняла только GET/HEAD, команд изменения настроек не было.

`renderEquipment()` ранее удалял все `details` через `replaceChildren()`. Исправление сохраняет четыре `details` и `summary` по фиксированным позициям существующего API и обновляет текст внутри них. Раскрытие, ручное закрытие и фокус клавиатуры сохраняются, а статусы и подписи контуров продолжают обновляться. Неизвестные данные обозначаются отдельно. API, GPIO, порядок карточек и команды оборудования не менялись.

## Оставшееся действие и граница приёмки

Для первого перехода требуется штатное подтверждение **v0.10.1** в **Настройки → Сервис → Обновление** на панели либо в сопряжённом браузере. Без действующей сессии веб-команды отвергаются; PIN показывается только на физическом дисплее и не обходится.

После подтверждения следует дождаться нового запуска v0.10.1, здорового интерфейса и подтверждённого состояния приложения. При сетевой приёмке фиксируются действительные статусы и внутренние проверки OTA worker; её нельзя называть независимым внешним чтением Flash. Otadata и `bp-update` NVS при OTA меняются ожидаемо. Не выполнять USB-сброс в `PENDING_VERIFY`.

**На момент этого отчёта не выполнены:** установка v0.10.1 по сети, аппаратное отключение питания во время OTA, осмотр и касания человеком. Вход присутствия остаётся отдельной задачей. Выравнивание четырёх температур готовится следующим этапом по последнему порядку пользователя и не входит в неизменяемый выпуск v0.10.1.
