`prerelease=false`, latest. Все четыре public assets отдельно скачаны по обычным

`5f7dadeb33a9864d72b7c36c0dc20cb2b1216619`; оно не меняет исходник/тег прошивки.
Первая попытка остановилась в draft и не выставляла неполный пакет как latest.

После read-only USB reset панель сама начала автоматическую проверку на 30-й секунде.
В **06:16:22 UTC**, при uptime 40 секунд, получено:

```json
{"version":"v0.10.0","started":true,"supported":true,"phase":"current","latest_version":"v0.10.0","busy":false,"error_code":0,"last_check":1793859382}
```

Сообщение устройства: **«Установлена актуальная версия. Манифест GitHub проверен.»**
Эта ветвь `Current` для равной версии выполняется только после HTTPS-чтения API,
загрузки манифеста через разрешённый GitHub CDN redirect и проверки его полей.
Тем самым проверены реальный сетевой путь API/asset, TLS и parser на панели;
загрузка нового приложения и переключение слотов по сети этим тестом не выполнялись.
После проверки Wi-Fi/тач/microSD оставались готовы, свободная heap — 303 148 байт.

`automatic_rollback=false` и `rollback_available=false` здесь ожидаемы: это первая
USB-установка OTA-клиента, сохранённого предыдущего OTA-слота ещё нет. Перед первым
OTA backend проверит известное USB-состояние и подтвердит текущее приложение.
Эти поля не являются событием произошедшего отката.

## Доказательства поддержки отката

Из закреплённого SDK `esp32p4_es/bin/bootloader_qio_80m.elf` командой
esptool 5.1.0 `elf2image --flash-mode dio --flash-freq 80m --flash-size 16MB`
воспроизведён побайтно совпадающий загрузчик: 21 616 байт, SHA-256
`6a88d429ece0ae20f8ae18493b9f3dee05c35f4abaa22f0320e44c34d30631c2`.
SHA-256 ELF — `982a0b6299689ed8d3b1267dc032f7f9cdcbd3b93fc46c9d15d7be3e60c9f0ce`.

Независимая проверка disassembly подтвердила записываемые переходы
`NEW → PENDING_VERIFY`, `PENDING_VERIFY → ABORTED` и исключение INVALID/ABORTED
из допустимых образов. Это проверка скомпилированной логики, а не только sdkconfig.

В окончательной target ELF найдены strong symbols:

```text
4004a46a T panel_update::deferArduinoConfirmation()
400541f6 T initArduino
4004a7e6 T verifyRollbackLater
```

Disassembly `initArduino` подтверждает вызов strong hook и обход раннего
`esp_ota_mark_app_valid_cancel_rollback`. Новая OTA-прошивка получает независимый
deadline 60 секунд до setup; подтверждение требует правильных версии/слота/хеша,
наличия fallback и 10 секунд здоровых heartbeat интерфейса.

## Границы аппаратной проверки

**Эта установка выполнена через USB. Полный последующий цикл установки новой
версии по HTTPS и физическое отключение питания во время OTA не выполнялись.**
Host fakes проверяют реальные ветви адаптера, но заменяют криптографию, транспорт
и Flash; они не доказывают реализацию TLS/SHA в SDK или физический power-loss.

`touch_ready` и GUI heartbeat не заменяют осмотр дисплея и касания человеком.
Реальный успешный ввод PIN, внешние датчики, MQTT-брокер и вход присутствия не
проверены. Вход присутствия в v0.10.0 не реализован. HTTP/MQTT интерфейсы остаются
для доверенной LAN; GitHub OTA отдельно использует HTTPS с проверкой сертификатов.
