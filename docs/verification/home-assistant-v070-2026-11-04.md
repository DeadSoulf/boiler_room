- [microSD / web — SUCCESS](https://github.com/DeadSoulf/boiler_room/actions/runs/41798561341).

MQTT workflow компилирует C++ с `-Wall -Wextra -Werror -pedantic`, проверяет 12 Discovery-конфигураций, JSON, неизвестные/просроченные данные, корректный 0 °C, переполнение millis, ограниченные буферы. Настоящий `panel_ha.cpp` исполняется с изолированными host-заменами NVS/MQTT/FreeRTOS: выключенный старт, ошибки записи, повреждение последнего слота, возврат к валидному, защита пароля при смене сервера, точный HA birth-topic и удаление собственных Discovery-тем. Это программные замены, **не настоящая сеть**.

Node.js-тест исполняет реальные функции веб-формы: сопряжение/подтверждение LAN, сохранение ревизии, dirty edits, keep/set/clear пароля, очистка поля после отправки и при завершении сессии. Есть проверки HTML-ID и синтаксиса. Геометрия реального браузера этим тестом не проверяется.

На Windows локально C++ host-тесты явно пропущены из-за отсутствия g++; в GitHub Ubuntu они выполнены успешно. Локальные JavaScript/static guards выполнены. В MQTT workflow также проходят прежние защитные тесты прошивальщика; COM3 ими не открывается.

Общий старый workflow `Boiler panel build and tests` по-прежнему имеет отдельный известный блокер host-моков Wi-Fi — [Issue #15](https://github.com/DeadSoulf/boiler_room/issues/15). Его состояние не подменяется успехом нового MQTT workflow.

## Границы и следующие проверки

MQTT/TCP без TLS, только доверенная LAN; функция по умолчанию выключена. Настройки только после физического сопряжения, пароль не возвращается API. Нет силовых команд и импорта удалённых показаний в конфигуратор входов.

До завершения аппаратной приёмки нужны: отдельно разрешённая безопасная прошивка; реальный брокер и интеграция MQTT в HA; неверные учётные данные; перезапуск HA/брокера и разрыв Wi-Fi; сохранение настроек после перезапуска панели; устаревание и отсутствие настоящих датчиков; выключение функции и проверка удаления её Discovery. Пароли вводить только в локальной веб-панели, не в GitHub.
