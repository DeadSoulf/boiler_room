## Поведение

- При сохранённой сети и включённом автоподключении первая попытка выполняется
  сразу, но уже принятые команды пользователя имеют приоритет.
- После неудачи либо потери работающего соединения паузы составляют
  **15, 30, 60, 120, 240 и далее 300 секунд**. Отсчёт после окончания попытки.
  После подтверждённого соединения с IP последовательность сбрасывается.
- Пауза не блокирует worker: он продолжает принимать команды каждые 100 мс.
  Сама попытка использует существующий ограниченный worker-путь: 20 с без
  ассоциации своей сети, до 60 с при ассоциации и ожидании DHCP. Во время
  попытки обычные радиокоманды заняты, Disconnect/Forget отменяют её с опросом
  каждые 100 мс. Синхронные вызовы SDK запуска/поиска завершаются прежде отмены.
- Автоматические попытки резервируют состояние занятости под тем же mutex,
  что и пользовательский mailbox. SDK auto-reconnect отключён: второй
  независимый цикл не может вмешиваться в паузу или поиск сетей.
- Перед каждой попыткой NVS читается заново; проверяются размер, magic, open,
  завершение строк и пароль. Временные копии стираются. Пароль и его длина
  не попадают в журнал или `RadioState`; нет периодических записей NVS.
- Disconnect/Cancel/Forget запрещают повторы в RAM даже при ошибке отключения
  радио или записи NVS. Если запись не удалась, ранее сохранённое значение
  может снова действовать после перезагрузки; интерфейс сообщает ошибку NVS.
- Ручной Connect отменяет прежний план. При ошибке новых данных старая сеть
  сама не подставляется в текущем запуске. После успешного подключения и
  сохранения новых данных supervisor включается заново. Старые настройки
  остаются в NVS при неудаче замены, как прежде.
- Кнопка «Отключить Wi-Fi» доступна и во время паузы. Сохранены подтверждения
  отключения/забывания, ручной поиск, BLE и существующее восстановление STA.
- Подключённая сеть не прерывается периодически. Веб, MQTT и OTA получают
  прежнее достоверное состояние соединения; их восстановление на настоящем
  устройстве требует отдельного испытания.

## Проверки

`bash tests/run_radio_tests.sh` проходит: прежние admission, scan, transition,
optional Wi-Fi/BLE ветви и новый `radio_reconnect_tests.cpp`.
Новый тест исполняет настоящий boot worker с синтетическим роутером,
появляющимся через 90 с, полную последовательность пауз и millis wrap,
потерю/восстановление сети, приоритет очереди, отмену, Forget, отказ NVS,
повторное чтение изменённых данных, неудачную/успешную ручную замену сети,
открытую сеть, ошибки запуска/режима/восстановления и DHCP через 25 с/таймаут.
Проверяются отсутствие NVS-записей в повторах и отсутствие пароля в снимке/журнале.

`tests/calm_ui/host.cpp` дополнен настоящими pointer-событиями LVGL для
отключения из idle/offline-паузы, отмены диалога и подтверждения.
Штатный workflow `Boiler panel build and tests` уже вызывает radio-набор
и сохраняет `artifacts/radio.log`; новый тест включён в него без отдельного workflow.
Локально прошли radio, `config_060_static.py`, `web_firmware_tests.py`,
`home_assistant_tests.py`, `storage_static_tests.py`, `sensors_static_tests.py`,
`check_release_version.py` и `git diff --check`. Новый reconnect-тест также
прошёл AddressSanitizer и UndefinedBehaviorSanitizer; LeakSanitizer в этом
окружении не работает под ptrace, поэтому проверка утечек отдельно не выполнена.
Локальный полный native bootstrap остановлен ограничением сети: закреплённый
LVGL через GitHub Git URL вернул HTTP 403; это не ошибка компиляции.
Точные результаты финального GitHub CI будут записаны после завершения.

Это adapter/host-проверки, не испытание RF, C6, настоящего DHCP или NVS.
Устройство не прошивалось, `VERSION`, `panel::VERSION`, `installed.json`
и опубликованные файлы v0.10.5 не менялись. Кандидат нового выпуска и штатный
OTA возможны отдельным этапом по [процессу выпуска](../RELEASE_PROCESS_RU.md).
