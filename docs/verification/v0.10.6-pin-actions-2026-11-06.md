## Поведение

- В «Настройки → Датчики» 11 доступных GPIO являются настоящими кнопками.
  Доступны мышь, Tab/Enter/Space и закрытие через Escape с возвратом фокуса.
  Питание, GND, BOOT, C6 и I2C остаются справочными контактами.
- Окно показывает GPIO, номер контакта JP1, текущее назначение и последствия
  выбранного действия. Можно назначить один из четырёх температурных DS18B20
  либо нижний/верхний геркон топлива. Для нового геркона NO/NC выбирается явно;
  сохранённая полярность не подменяется.
- Перенос выбранного канала и освобождение прежнего владельца GPIO выполняются
  одной конфигурацией. Автоматического обмена двух каналов местами нет.
- Занятый пин можно освободить после подтверждения. Открытие окна, выбор в форме
  и отмена не записывают настройки.
- Новый диалог сохраняет черновик при опросах. Изменение revision в другом окне,
  недостоверный снимок, потеря связи, завершение сеанса и OTA блокируют запись.
  HTTP-ответ сам по себе не подтверждает успех: требуется последующий свежий GET
  с ожидаемыми revision и всеми шестью назначениями. Автоповтора POST нет.
- Старая дополнительная форма источников и прежние API сохранены для
  совместимости. Проверка expected revision относится к новым операциям
  `connection_pin_set` / `connection_pin_clear`, а не к старому `connection_set`.

## Сохранение и ошибки

Новые команды проходят существующие auth/Origin/OTA guards. Revision проверяется
под конфигурационным mutex, после чего формируется и проверяется целый снимок.
Успешная операция записывает один config blob, читает его обратно и только тогда
активирует его. No-op возвращает прежний revision без записи NVS.

Ответы: `200 saved/revision`, `400 invalid_pin_fields/invalid_pin_assignment`,
`409 stale_revision`, `503 configuration_unavailable/configuration_write_failed`.

При ошибке put/read-back выполняется попытка восстановления исходного inactive
blob. Rollback допускает только строго более старую revision с учётом uint32
wrap. Повторное переключение двух последних принятых конфигураций сохранено.
Постоянный отказ восстановления NVS или потеря питания между операциями не даёт
гарантии прежнего состояния после reboot в schema 1. Fault-тест это явно
воспроизводит; интерфейс сообщает о неподтверждённом результате и требует
перечитать назначения. Аппаратное испытание отключением питания не выполнялось.

## Выпуск и устройство

Явный выпуск запускается одним прямым commit main, увеличивающим VERSION,
с точным сообщением `release: vX.Y.Z GitHub OTA candidate`. Обычный feature push
не публикует. Сохранены проверки source/ref/parent/версии, успешные jobs,
ID артефактов одного запуска, input hashes, прежний publisher, проверка тега и
повторное публичное скачивание. До конца `verify-public` main перемещать нельзя.

До последнего запрета пользователя read-only запросы `/health`, `/api/status` и `/` с Asus по известному адресу
панели не ответили за ограниченный timeout 06.11.2026, начало проверки
`2026-11-06T03:54:59.929287+00:00`. Текущая версия устройства неизвестна.
Настройки, GPIO, Flash и USB устройства в этой задаче не менялись. После выпуска
нужна штатная установка подтверждённой версии через GitHub OTA и отдельная
сетевая/физическая приёмка. Публикация сама по себе установкой не считается.
