## 2. Последний незавершённый запрос

Пользователь попросил:

> Добавь субагентов чтоб тебе помогали.
> Добавь функцию обновления, чтоб панель видела что вышло новое обновление на githab и предлагала его установить, чтоб было видно ход обновления.
> добавь функцию присутствия, на один из пинов выведу датчик с сухим контактом чтоб при присутствии он замыкался на gnd и в этот момент включался дисплей, миную алгоритм Подсветка и пробуждение касанием.
> И обнови панель.

**Субагенты:** механизм реально проверен и использован при установке v0.9.1. Отдельный агент проверил GitHub/CI/слияние и код адаптера USB-чтения; его замечание исправлено до запуска. Для будущих OTA/присутствия разделять независимые части без параллельной записи одних файлов; итоговую сборку/установку/релиз координирует основной исполнитель.

**Обновление:** обнаруживать новые релизы собственного GitHub и предлагать установку; показывать этапы/прогресс и ошибки. Установка без выбора пользователя не запрошена. Рабочего OTA-клиента на панели пока нет; опубликованный desktop ZIP не означает готовое обновление по сети. Нужны проверка совместимости/источника/целостности, безопасная запись и подтверждённый сценарий восстановления; подробный инженерный план в полной сводке.

**Присутствие:** отдельный сухой контакт замыкается на GND → включить дисплей независимо от текущего сна и ожидания касания. Конкретный GPIO **не задан**, датчик не считать уже подключённым. Выбрать/настроить подтверждённый свободный вход JP1 с защитой от конфликтов и дребезга. Поведение удержания/задержки после размыкания ещё не определено пользователем; выбранный вариант обозначить явно. Не превращать сигнал присутствия в нажатие и не ломать сопряжение.

**Установка результата уже явно запрошена последней фразой.** После реализации/проверок она выполняется в пределах этой задачи с backup и синхронизацией GitHub. Предыдущее сохранение контекста было документационным. В новом чате пользователь отдельно попросил «Обнови на устройстве»; установлена подготовленная v0.9.1 со значками. OTA/присутствие остаются незавершёнными. Не спрашивать заново уже известные данные только из-за смены чата; реальные неизвестные параметры не выдумывать.

## 3. Сохранённые решения интерфейса

- Горизонтальные свайпы: Главная → Оборудование → Топливо → Настройки. Нижних кнопок нет; часы на главной, «Домой» на остальных, вложенный «Назад». Меньше информации сразу, подробности по касанию. Дата/настройка часов только в вебе.
- Карточки: в доме, на улице, теплоноситель, топливо. Подпись «В доме» и значки дома/солнца с облаком/радиатора входят в установленную v0.9.1. Название проекта «Котельная» сохраняется. Значки декоративные, не прогноз и не индикация включённого отопления.
- Канистра уже в v0.9.0: внутри карточки топлива, небольшая температура над ней, нижняя отдельная кнопка удалена. Для двух ReedNC: оба разомкнуты — полная; замкнут верхний — половина; оба замкнуты — пустая с «!». Только нижний замкнут — ошибка; нет/устарели данные — неизвестно, не полный бак. Полярность/GPIO не назначались автоматически.
- «Сопряжение» в браузере запрашивает код; дисплей просыпается, открывает главную и показывает код слева от часов. Правильный ввод, отмена или 120 секунд скрывают его. Физический раздел «Веб-доступ» удалён. Код не отдаётся API/MQTT и не публикуется. Реальный успешный ввод человеком не проверен удалённо, тестовый цикл LVGL/Chromium прошёл.
- Веб: четыре главных раздела, вложенные настройки; Wi-Fi/BLE/экран/часы/датчики/MQTT/microSD сохранены. После прошивки обновить браузер Ctrl+F5.
- Home Assistant: 12 MQTT Discovery-сущностей только для чтения. На последней проверке модуль готов, **выключен**, настоящий брокер не испытан. HTTP/MQTT без TLS — только доверенная LAN. Пароли вводить локально, не в чат/GitHub. Импорт Modbus/MQTT-показаний в конфигуратор входов не реализован.
- Силовых команд нет. Реальные датчики ещё не подключены/не испытаны, последняя ревизия входов 0. Подогрев до 80 °C — требование, не готовый действующий алгоритм.

## 4. Как работаем и проверяем

Работаем по-русски через GitHub; сохраняем чужие изменения и проверяем актуальные ветки. Не смешиваем панель с ESP32-S3, HEATER BENCH, PM02, HomeAiCore. Пользователь сказал «ты спешишь»: не начинать несвязанный следующий этап и не прошивать макет без запроса. Но выполнять уже разрешённую работу самостоятельно, не заменять её обещанием патча.

Перед установкой проверить плату/разделы/OTA и исходник, создать **новую полную резервную копию текущего приложения**, записать только разрешённый раздел, полностью считать обратно и проверить HTTP. NVS/C6/bootloader/SD не стирать. Проверку сборки не выдавать за касания, подключённые датчики или настоящий MQTT-брокер.

**Без напоминания синхронизировать после разрешённой установки:** код main, VERSION/версия приложения, тег на источник сборки, GitHub Release с пакетом/SHA-256, README/CHANGELOG, аппаратный отчёт, installed.json и эта памятка. Правило находится в [AGENTS](../AGENTS.md) и [RELEASE_PROCESS_RU.md](RELEASE_PROCESS_RU.md). Для чисто документационного сохранения не придумывать новую прошивку/релиз.

Ранее доступны GitHub, Desktop Commander, Figma (права конкретного файла проверять; место команды View), Designer. На Asus использовались PlatformIO/esptool, WSL C++/CMake, настоящий LVGL и Playwright/Chromium. Это не автоматически запущенные субагенты. Проверить доступность в новом чате.
