# Как мы работаем — памятка для нового чата

**Проект:** сенсорная панель котельной GUITION JC4880P443C_I_W, ESP32-P4 + ESP32-C6. **GitHub:** https://github.com/DeadSoulf/boiler_room, основная ветка `main`.

## Наш порядок работы

1. **Сначала восстанавливаем контекст**: читаем этот файл, [README_RU.md](../README_RU.md), [AGENTS.md](../AGENTS.md), актуальные коммиты, открытые Issues и PR. GitHub — основной источник кода и решений; сведения о состоянии панели проверяем отдельно.
2. **Работаем по-русски, последовательно и предметно.** Пользователь описывает задачу — ассистент самостоятельно проверяет код, вносит необходимые изменения, запускает подходящие тесты и сообщает результат. Уже известные данные повторно не спрашиваем; ошибки не скрываем.
3. **Не теряем чужие изменения.** Проверяем ветку и `git status`, не затираем незакоммиченные файлы на Asus. Для крупных доработок используем отдельной ветки/PR; после проверки и по запросу обновляем `main`. В GitHub фиксируем документацию, результаты и ограничения.
4. **Не смешиваем проекты.** Эта панель — отдельный проект; HEATER BENCH, PM02, экспериментальные ESP32-S3, HomeAiCore и другие контроллеры не переносим сюда без явного решения пользователя.
5. **Прошивка панели — только по явному запросу.** Панель подключается к компьютеру **Asus, COM3**; доступность соединения проверять заново. До записи — совместимость платы, хеши образа, загрузчик/разделы/OTA, полная локальная резервная копия текущего приложения. Пишем только нужный раздел, считываем обратно и проверяем. Не стираем NVS, ESP32-C6, microSD и другие разделы без отдельного согласования. Backup и секреты не публикуем в публичном GitHub.
6. **Никаких вымышленных данных и опасных команд.** Не изображаем датчик подключённым без реального измерения. Силовое управление котлами, отопителем, насосами и реле не включаем до согласования аппаратной схемы и защит.
7. **После каждого существенного этапа** обновляем код/тесты/README, фиксируем фактическую проверку и актуализируем эту памятку (версию, статус и следующие задачи). Если задача не завершена — пишем, что именно осталось.
8. **Не спешим к следующему этапу.** Пользователь отдельно указал, что не хочет поспешных переходов к настройке или прошивке. Новый интерфейс сначала показываем для оценки, не устанавливаем автоматически.

[Экраны и сравнение](https://github.com/DeadSoulf/boiler_room/blob/feature/calm-panel-menu-v0.8.0/docs/calm-menu/README.md), `preview.html` в том же каталоге — самодостаточный офлайн-просмотр. Снимки получены настоящим LVGL; все значения в них тестовые. **Не установлено на устройство.** Следующий шаг — оценка пользователем вида и навигации, не автоматическая прошивка.
- **Проверки v0.8.0:** 334 нативные проверки расположения, 0 обрезанных надписей, реальные pointer-события и 240 перестроений; target-сборка ESP32-P4 SUCCESS. Радио/MQTT/датчики/NVS/SD/веб-драйверы не менялись. Новый workflow `Calm physical menu`; его актуальный результат читать на GitHub. Прежний общий CI #15 — отдельная проблема.
- **Установлена v0.7.0**, а не v0.6.2: 04.11 по отдельному запросу записано приложение с полным резервированием и побайтной проверкой. После подключения к Wi-Fi пользователь сообщил `http://192.168.144.207/`; GET `/health`, `/`, `/api/status` подтвердили v0.7.0, Wi-Fi, готовность тача, microSD mounted/logging и готовый модуль HA. **MQTT выключен**, реального соединения с HA-брокером ещё нет. Во время разработки нового меню устройство не менялось; доступность проверять заново.
- В `main` пока исходники v0.6.2, а код установленной v0.7.0 — в `feature/home-assistant-mqtt-v0.7.0`, [PR #16](https://github.com/DeadSoulf/boiler_room/pull/16). Новый UI основан на этой ветке, чтобы не потерять интеграцию HA.
- **Home Assistant:** MQTT Discovery, 12 сущностей только для чтения, веб-настройки брокера после физического сопряжения. MQTT/TCP без TLS, только доверенная LAN. Пароли вводятся локально, не в чат/GitHub. Импорт удалённых датчиков и силовое управление не включены.
- Четыре температуры и два геркона имеют защищённые назначения входов JP1; реальные датчики ещё не подключены/не испытаны, настройки входов пустые. Семь элементов отопительного оборудования отображаются как неподключённые; команд силового управления нет. Modbus/MQTT в конфигураторе источников — пока не работающие входные драйверы.
- Общий CI требует исправить старые Wi-Fi/BLE host-моки: [Issue #15](https://github.com/DeadSoulf/boiler_room/issues/15). Отдельные safety-проверки успешны.
- Экспериментальные Neon/exFAT — [PR #10](https://github.com/DeadSoulf/boiler_room/pull/10), не часть установленной v0.7.0 и не база нового спокойного меню. exFAT не считать работающим драйвером.
