# Загрузка визуализации на JC4880P443 через COM3

Этот пакет предназначен для **GUITION JC4880P443, ESP32-P4 ES v1.3, Flash 16 МБ** с уже установленными загрузчиком и таблицей разделов, совпадающими с проверенной сборкой проекта. Он обновляет приложение панели. Управление оборудованием в визуализации демонстрационное; реальные выходы не назначены.

`flash_COM3.cmd` записывает приложение после проверок и резервирования. Обычный запуск `flash_panel.py` без `--write` выполняет проверку подключения и совместимости без записи Flash. Само подключение esptool переводит панель в загрузчик; после успешной проверки скрипт перезапускает её.

## Подготовка

1. Распакуйте **весь** архив в отдельную папку на компьютере, к которому подключена панель. Не запускайте `.cmd` внутри ZIP.
2. Закройте Arduino Serial Monitor, терминал PlatformIO и другие программы, использующие **COM3**.
3. Нужен Python **3.10 или новее** и **esptool 5.1.0**. Эта версия esptool совпадает с инструментом зафиксированной target-сборки. При отсутствии зависимостей выполните в PowerShell из корня распакованного пакета:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install "esptool==5.1.0"
```

Установка скачивает esptool и его зависимости с PyPI. Она не нужна повторно для уже подготовленного окружения. Если `py` отсутствует, установите Python с [официального сайта](https://www.python.org/downloads/windows/), затем повторите команды.

## Запись

Запустите **`scripts\flash_COM3.cmd`** двойным щелчком. Скрипт предпочитает окружение `.venv` из пакета; иначе использует доступный `py -3` или `python` и проверяет точную версию esptool.

Если esptool 5.1.0 уже установлен в другом Python, выберите именно этот интерпретатор. Например, для существующего окружения PlatformIO сначала проверьте доступность пакета; наличие самого PlatformIO ещё не означает, что esptool установлен как импортируемый Python-пакет:

```powershell
$env:BOILER_FLASH_PYTHON = "$env:USERPROFILE\.platformio\penv\Scripts\python.exe"
& $env:BOILER_FLASH_PYTHON -c "import sys, importlib.metadata as m; print(sys.version); print(m.version('esptool'))"
.\scripts\flash_COM3.cmd
```

Переменная `BOILER_FLASH_PYTHON` имеет приоритет над `.venv` и `py`. Runner всё равно проверяет Python ≥3.10 и точную версию esptool; неподходящее окружение не используется для записи. Путь можно заменить на уже установленный подходящий Python. Автоматическая установка зависимостей в `.cmd` отсутствует.

Для одной только проверки:

```powershell
.\.venv\Scripts\python.exe scripts\flash_panel.py --port COM3
```

Явная запись из PowerShell:

```powershell
.\.venv\Scripts\python.exe scripts\flash_panel.py --port COM3 --write
```

При проблемах со скоростью можно указать `--baud 115200`; по умолчанию после подключения используется 460800. Пакет не ищет другие порты и не выбирает устройство автоматически вместо COM3.

## Что проверяется перед записью

- SHA-256 четырёх входных файлов: `firmware.bin`, `bootloader.bin`, `partitions.bin`, `binary-verification.json`.
- Тип образа ESP32-P4, его требования к ревизии, размер и соответствие отчёту сборки.
- Точный тип подключённого чипа, **ревизия v1.3**, Flash **16 МБ**. ESP32-C6 на другом USB-интерфейсе не принимается за панель.
- Отсутствие Secure Download Mode, Secure Boot и Flash Encryption. Скрипт прекращает работу с защищённым устройством, не меняя настройки защиты.
- Совпадение существующих загрузчика и таблицы разделов с пакетом. Отличающийся или пустой комплект требует отдельного разбора; автоматическая первичная установка не выполняется.
- Состояние `otadata`. В стандартной таблице два приложения: `app0` по адресу `0x10000` и `app1` по адресу `0x650000`. Скрипт определяет выбранный слот по данным OTA и CRC. Повреждённое, неподтверждённое или неизвестное состояние останавливает запись.

В одной и той же сессии соединения создаётся полная резервная копия выбранного раздела приложения и его загрузочных метаданных. Файлы записываются и проверяются на компьютере **до** изменения панели. Каталог выводится в окне; по умолчанию это `%LOCALAPPDATA%\BoilerPanel\backups\<дата-время-идентификатор>`.

Затем записывается **только выбранное приложение**. Загрузчик, таблица разделов, `otadata`, NVS, SPIFFS, второй слот и прошивка C6 не записываются. Команд полного стирания Flash или обхода проверок нет. Записанные байты считываются обратно и сравниваются с исходником; таблица и `otadata` повторно сверяются, после чего выполняется перезапуск.

Резервные копии относятся к конкретной плате и остаются на вашем компьютере. Не добавляйте их в GitHub и не помещайте в публичный архив.

## Проверка на панели

После сообщения об успешном чтении и перезапуске:

1. Дождитесь главного экрана и проверьте русский текст, ориентацию 480×800 и четыре температурных канала.
2. Перейдите свайпом в «Управление». Откройте бойлер, электрокотёл, дизельный отопитель и подогрев топлива.
3. Проверьте возврат и кнопку «Домой», три элемента контура, подпись «до 80 °C» только у топлива.
4. Проверьте версию в «Сервисе» и явно обозначенные демонстрационные состояния. Подтверждение демонстрационной команды не означает физическую работу оборудования.

Успех записи доказывает совпадение записанных байтов, но не видимость изображения или работу физического тача. Последние пункты проверяются на самом устройстве.

## Восстановление приложения

Сохраните исходный распакованный пакет и путь резервной копии. Для восстановления выберите **каталог**, содержащий `metadata.json` и `application.bin`:

```powershell
.\.venv\Scripts\python.exe scripts\flash_panel.py --port COM3 --restore "C:\путь\к\резервной-копии" --write
```

Перед восстановлением проверяются плата, контрольные суммы, активный слот и неизменность загрузчика/разделов/OTA. Текущее приложение также резервируется, даже если его заголовок повреждён прерванной записью. Проверяется заголовок сохранённого восстанавливаемого образа. Восстановление не меняет NVS, Wi-Fi-настройки или C6. Если скрипт сообщает о несовместимости, не подменяйте файлы и не запускайте `erase-flash` или `--force`: сохраните полный текст ошибки для проверки причины.

Если запись прервана питанием или USB, автоматического отката нет. Резервная копия остаётся в указанном каталоге. Если панель осталась в загрузчике после проверки или отказа, нажмите RESET. При занятом порту закройте программу, удерживающую COM3; если автоматический вход в загрузчик не сработал, используйте штатный способ входа платы, не меняя соединения по предположению.

## Состав готового пакета

```text
firmware.bin
bootloader.bin
partitions.bin
binary-verification.json
SHA256SUMS.json
scripts/flash_panel.py
scripts/flash_COM3.cmd
docs/flash-panel.md
```

`SHA256SUMS.json` содержит объект вида `{"firmware.bin": "<SHA-256>", ...}`. Четыре файла образов/отчёта обязательны. `bootloader.bin` нужен для сравнения, а не для записи.

## Проверка самого загрузчика

```sh
python3 tests/flash_panel_tests.py
```

Offline-тесты проверяют отказ до записи при неправильной плате, ревизии, защите, загрузчике, таблице, OTA и резервировании; выбор app0/app1; отсутствие записи без `--write`; запись только приложения; проверку чтением; восстановление и отказ для чужой/повреждённой копии. Они используют имитацию Flash и не подтверждают работу COM3, USB-драйвера, esptool или физической панели.
