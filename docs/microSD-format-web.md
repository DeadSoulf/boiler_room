# Форматирование microSD из веб-панели — v0.5.8

Встроенный HTTP-сервер ESP32-P4 предоставляет защищённый запрос на форматирование **только вставленной в слот microSD-карты** по SDMMC Slot 0. Функция предназначена для подготовки FAT, когда файловая система не читается, а также для сознательного полного стирания существующей FAT-карты.

## Как пользоваться

1. Подключитесь к панели по Wi-Fi в доверенной локальной сети и откройте `http://IP_ПАНЕЛИ/`.
2. Выполните сопряжение: на физическом дисплее «Настройки → Веб-доступ → Создать новый код»; введите одноразовый код в браузере.
3. В браузере откройте «Сервис → Накопитель microSD». Ознакомьтесь с предупреждением, что **все существующие файлы и разделы microSD будут уничтожены**.
4. Введите точную фразу `СТЕРЕТЬ MICROSD` и нажмите «Запросить форматирование microSD». Подтвердите действие в диалоге браузера. Сам HTTP-запрос **не меняет карту**.
5. В течение 90 секунд на **физическом дисплее** откройте «Сервис», прокрутите до блока microSD и нажмите «Стереть microSD» либо «Отменить». В отсутствие этого физического подтверждения ничего не форматируется.
6. После подтверждения карта форматируется отдельной задачей, не блокируя LVGL и HTTP. Браузер показывает «В очереди / Форматирование / Проверка / Готово / Ошибка».
7. Успешный результат подтверждается размонтированием, повторным монтированием FAT и пробной записью/чтением `/boiler-panel/logs/events.log`. Показываются реальный объём и свободное место.

## Безопасность

- **Никакого автоформатирования при включении.** Нормальный `SD_MMC.begin` всегда вызывается с `format_if_mount_failed=false`.
- Запуск возможен исключительно после физического сопряжения браузера, точной подтверждающей фразы, дополнительного диалога и нажатия на самом дисплее; код действует 90 секунд.
- Не более **одной попытки форматирования на загрузку панели**, включая неудачную, без автоматического повтора.
- Подготовка выполняется только на ESP32-P4 через SDMMC Slot 0. Не используются диски ноутбука, встроенная Flash, NVS, загрузчик или ESP32-C6.
- Для FAT применяется штатный ESP-IDF `esp_vfs_fat_sdmmc_mount` и `esp_vfs_fat_sdcard_format`; результат зависит от формата/ёмкости карты и версии FATFS. На стандартной microSD подходящего размера ожидается FAT32, но на небольших носителях библиотека может выбрать FAT16. Это не операция «без потери данных».
- На время форматирования очередь журнала очищается; пользовательские файлы на карте уничтожаются именно по подтверждённому запросу.
- Не отключайте питание и не извлекайте карту во время форматирования.
- Если носитель неисправен, чтение не поддерживается или форматирование завершилось ошибкой, веб-панель показывает сбой. На остальные подсистемы панель продолжает работать, но содержимое microSD уже может быть повреждено. Автоматических повторов нет.

## API

- `GET /api/status` → `storage`: `format_state` (0–8), `format_attempted`, `format_remaining_s`, `format_message` и прежние показатели объёма.
- `POST /api/command` с Bearer-токеном сопряжения и формой `action=sd_format_prepare&confirm=СТЕРЕТЬ MICROSD` ставит запрос в очередь ожидания физического подтверждения. Успешный ответ HTTP 202 **не означает, что карта уже стирается**.
- Нет HTTP-эндпоинта, который самостоятельно начинает форматирование. Только физическая кнопка из задачи LVGL переводит запрос к исполнению в фоновом SD-работнике.

Состояния: 0 нет запроса, 1 ожидание кнопки на панели, 2 в очереди, 3 форматирование, 4 проверка, 5 готово, 6 ошибка, 7 отменено, 8 истекло время.

## Проверка

Собрать `jc4880p4`, прогнать `tests/storage_static_tests.py`, `tests/web_firmware_tests.py`. На реальной панели проверить HTTP 200, видимость страницы и статус `format_state=0`; не отправлять разрушительную команду автоматически в smoke-тестах. Для проверки собственно форматирования потребуется явное действие человека на дисплее.

**Примечание:** наличие кода и успешно собранной прошивки само по себе не подтверждает успешное форматирование конкретной карты.
