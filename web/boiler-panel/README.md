# Веб-интерфейс панели котельной

Интерактивная демонстрация согласованного интерфейса дисплея 480×800 с адаптацией для компьютера и телефона. Это отдельное статическое приложение: оно не заменяет прошивку ESP32 и не подключается к реальным датчикам или нагревателю.

## Разделы

- **Обзор:** четыре температуры («В котельной», «На улице», «Теплоноситель», «Топливо»), уровень, кнопки подогрева, график и последние события.
- **Топливо:** верхний и нижний герконовые пороги, дискретный диапазон уровня, температура, обозначение «до 80 °C», включение и выключение режима.
- **История:** четыре температурных канала, периоды 1/6/24 часа, минимум, среднее и максимум по демонстрационному ряду.
- **Журнал:** события текущей вкладки, фильтры, отметка «Прочитано» и экспорт CSV.
- **Диагностика:** известность, свежесть, согласованность показаний и доступность канала команд в выбранном примере.
- **Сервис:** параметры демонстрации, выбор сценария и начало новой сессии.

Общее предупреждение сохраняется при переходах между разделами. На больших экранах доступны боковое меню и переключение в окно 480×800; на узких — нижняя навигация.

## Запуск

Сборка и установка зависимостей не требуются. В этом каталоге:

```sh
python3 -m http.server 8080 --directory dist
```

Откройте `http://localhost:8080`. Приложение использует ES-модули, поэтому запускать его следует через HTTP, а не двойным нажатием по HTML в файловом менеджере. Достаточно отдавать пять файлов из `dist/` любым статическим сервером. Внешние шрифты, библиотеки, CDN и API не используются.

```sh
node tests/model.test.mjs
```

Проверено на Node 24.22.1. Папка `tests/` нужна только для проверки, а не для работы интерфейса.

## Демонстрационные сценарии

Кнопка «Сценарии» открывает семь примеров: рабочий диапазон, разрешённый подогрев, верхний уровень, мало топлива, несогласованные датчики, устаревшие данные и отсутствие подключения.

Каждый сценарий — фиксированный снимок, а не поток реальной телеметрии. Нажатие кнопок не нагревает топливо и не меняет показания температуры. Исторические ряды синтетические, повторяемые и явно отмечены в интерфейсе. У устаревшего снимка история заканчивается последним известным показанием; текущая температура скрыта. При отсутствии данных история пуста.

## Подогрев и уровень

В интерфейсе различаются **разрешение режима** и **фактическое состояние нагревателя**. Демонстрационные команды меняют разрешение и добавляют событие в журнал; состояние физического нагревателя остаётся неизвестным.

Для демонстрации включение доступно при известном режиме, доступном канале команды, свежей температуре топлива и согласованных свежих уровнях с достигнутым нижним порогом. Это предварительные правила доступности кнопок, **не проект аппаратной защиты**. Доступное выключение не блокируется из-за плохих показаний уровня или температуры. При отсутствии канала команды обе кнопки недоступны с пояснением.

«До 80 °C» сохраняет формулировку пользователя. Она не назначает целевую уставку, гистерезис или аварийную отсечку. Автоматического регулятора в приложении нет.

Два геркона дают дискретные диапазоны, а не проценты и литры. Цветная область бака показывает диапазон между порогами. Сигналы нормализованы; GPIO, NO/NC, электрическая полярность, подавление дребезга и аппаратный контроль линии не определены. Устаревшее показание не считается состоянием «ниже нижнего».

## Данные и дальнейшее подключение

`dist/model.js` — чистая модель с отдельными показаниями и временем обновления. `dist/app.js` — отображение, локальные взаимодействия и навигация. `dist/styles.css` — оформление и адаптивность.

Данные и журнал хранятся только в памяти текущей вкладки. При перезагрузке команды не восстанавливаются и начинается новая демонстрация. Модель ограничивает журнал 100 событиями. Отметка события прочитанным не убирает действующую причину предупреждения.

Для реального подключения ещё нужен согласованный протокол телеметрии и команд: достоверность и возраст каждого входа, подтверждение команд контроллером, обратная связь нагревателя, обработка отказов и права доступа. Показатели этой демонстрации и локальный обработчик `setHeating` не должны использоваться как подтверждение выполнения физической команды.
